## Performance and maintenance

- The sidebar caches filtered changes and the directory tree. Paths are split once per rebuild; each node stores its subtree file count. Counts include both a removed file and its added descendants during file/directory transitions.
- Text layout retains at most three sets of natural row-height measurements, invalidates them for source/font changes, and avoids reapplying paragraph attributes when alignment is unchanged. Existing alignment tests revisit cached widths. U+2029 paragraphs receive one alignment gap at the end of their source row.
- Removed the unused longest-line scan and published state, and the unused `GitComparison.isIdentical` calculation.
- Input validation still runs synchronously when accepting an editor draft, preserving immediate validation errors and the rejected draft. The opt-in `measureLargeInputValidationAndTextLayout` test measures it separately from layout before making further scheduling changes.
- Added macOS CI for the complete suite and development bundle verification. Optional workflow-dispatch measurements cover 100,000 lines, long wrapping lines, Unicode input, initial display, resizing, and font changes. Timings are reported without inventing a universal threshold.
- Git stderr is now a drained pipe with a 16 KiB retained diagnostic, rather than an unbounded temporary file.

## Validation and manual checks

The Linux cloud environment supports Swift 6.0.3 and the portable core suite. Mac-only tests and measurements require a macOS runner; their presence is not evidence they passed. GitHub Actions retains build/test logs.

Local validation: all 62 portable tests passed, the development build passed, macOS source/test syntax parsed with the macOS target, workflow YAML parsed, and shell syntax/patch whitespace checks passed. Parsing macOS syntax does not type-check against AppKit or exercise UI behavior.
